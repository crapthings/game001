# 道具配置规范 v2

目标：每种道具承担明确的生存、采集或建设用途。先维护少量基础物品，不加入纯卖钱垃圾、收藏品、稀有度梯度或无功能变色版本。

## 文件与开发预览

- `src/game/inventory/definitions/basicItems.js`：以物品 ID 为键的基础道具配置。
- `src/game/inventory/definitions/categories.js`：以分类 ID 为键的分类配置。
- `src/game/inventory/items.js`：统一注册、字段校验、只读目录，保留现有 `itemCatalog[id]` 接口。
- 游戏内 F2 → 道具图鉴：浏览全部配置，搜索名称、ID、文案、用途和来源，按类型与用途接入状态筛选。
- 图鉴是只读预览，不发放物品，不改变背包或世界；筛选条件不持久化。

## 定义字段

| 字段 | 规范 |
| --- | --- |
| 对象键 / `id` | 配置对象键是唯一稳定的英文 camelCase ID；注册时自动注入 `id`，值内不重复填写，写入存档后不能随意改名 |
| `categoryId` | 必填：`food`、`water`、`medical`、`material`、`tool` |
| `name` | 必填，中文显示名，直白说明是什么 |
| `description` | 必填，一到两句末日生活故事或冷幽默；不承载效果数值 |
| `purpose` | 必填，明确用于什么操作或产出；不写“以后可能有用” |
| `uses` | 非空用途列表：`consume`、`heal`、`craft`、`build`、`repair`、`harvest`；是分类，不是自动执行逻辑 |
| `status` | `ready`：用途已接入；`planned`：用途确定但系统尚未接入。不是稀有度，也不等同于已开放掉落 |
| `symbol` | 当前 UI 的文字占位图标；正式图片图标后续独立扩展 |
| `weight` | 单件千克数，有限正数 |
| `maxStack` | 单格数量上限，正整数；工具为 1 |
| `sources` | 非空的规划来源说明列表，供设计与图鉴展示；不执行掉落，也不包含掉率 |
| `effects` | 可选，目前只允许已接入消耗品的 `food`、`water` 正数效果；不能用虚构的治疗字段代替医疗实现 |

`category` 由 `categoryId` 统一派生中文，兼容现有 UI，不重复填写。目录加载时检查必填字段、枚举、数量、效果和重复 ID；注册结果只读。配置格式版本由 `ITEM_SCHEMA_VERSION` 标识，与背包存档版本独立。

```js
{
  water: {
  categoryId: 'water',
  name: '瓶装饮用水',
  symbol: '水',
  description: '瓶身写着“源自纯净山泉”。山泉还在不在不知道，至少瓶盖没人拧过。',
  purpose: '饮用恢复 35 点水分。',
  uses: ['consume'],
  status: 'ready',
  weight: 0.55,
  maxStack: 4,
  sources: ['民居', '商店', '营地'],
  effects: { water: 35 },
  },
}
```

## 首批范围：11 种

| 类型 | 道具 | 功能落点 |
| --- | --- | --- |
| 饮水 / 食物 | 瓶装饮用水、罐头 | 已接入水分与饱食度恢复 |
| 医疗 | 干净绷带 | 待接入包扎、止血 |
| 材料 | 树枝、石料、植物纤维 | 徒手采集，制作第一套工具，避免先有工具才能获取工具材料的死循环 |
| 材料 | 木料、布料、金属零件 | 据点、床铺、工具及维修的基础材料 |
| 工具 | 简易石斧、简易石镐 | 砍树、采石 |

只有饮水、罐头的用途已接入，其余是有明确消费方向的配置储备。新增待接入道具不自动进入掉落表、开局背包或世界生成；先完成用途，再开放获取。既有绷带、零件 ID 保留，兼容已有背包。

现有武器、弹药和手雷仍由战斗配置管理，本批不建立第二套重复定义。后续装备实例与容器整合时，再增加对应类型和显式战斗配置引用。

## 定义、实例与世界实体分开

- 定义回答“这是什么”：名字、文案、重量、用途等，全局共享。
- 现有背包堆叠仍是 `{ itemId, count }`，不复制名字、描述、重量到存档。
- 后续独立工具实例保存 `instanceId`、`itemId` 和耐久等变化状态；同一工具定义可对应多个不同耐久的实例。当前尚未加入耐久。
- 后续地面掉落实体保存实体 ID、位置、容器内容；树木与岩石是资源节点，通过采集规则产出道具，不直接把整棵树当背包物品。
- 掉落表、配方、建筑成本、采集产出各自配置并引用 `itemId`，不要把概率、生成位置和配方执行代码塞入物品定义。
- 普通感染者不产出武器、弹药、手雷或通用武器零件。布料等随身物品也不是必掉。

## 新增规则

1. 先说明道具解决哪个需求、从哪里来、最终被什么操作消耗或使用。
2. 已有道具能覆盖时优先复用，暂不拆分多个木材、矿石或食物等级。
3. 文案可以幽默，名称与用途必须容易理解；精确数值以效果配置为准，修改数值时同步用途说明。
4. 用途尚未实现就标 `planned`，不提供无效果的“使用”按钮，不投入正式掉落。
5. 变更已有 ID、堆叠上限或重量要评估旧背包有效性与迁移；不要靠修改定义静默破坏存档。

本次仅完成配置规范、基础目录和开发预览，不包含采集、配方、医疗或建造系统。按项目要求未运行测试、build 或 lint。

## 索引访问（v2）

```js
itemCatalog[drop.itemId]                   // 物品定义，负重、堆叠、效果直接取值
itemCategories.material                  // { id, name, itemIds }
itemCategories.material.itemIds          // 分类成员 ID，注册时生成一次
itemCategories[itemCatalog.wood.categoryId].name
```

物品定义仅存一份；分类成员不复制定义、不手动维护。多个配置包逐个注册并检查跨包重复 ID，不能先展开合并覆盖。单个 JS 对象也不得重复声明键（JS 会在注册前覆盖它们）。分类 ID 必须存在，引用错误在加载时报告。

`itemIds` / `itemDefinitions` 用于 UI 枚举；搜索匹配仍需遍历文本，分类列表从分类索引取成员，选中详情直接按 ID 读取。掉落按权重抽取是独立算法，不由 ID 索引替代。当前不额外引入掉落缓存或抽样算法。

此次只升级配置结构，原有物品 ID、数值及背包 `{ itemId, count }` 均不变，无需迁移背包存档。
