# 交互与掉落配置 v1

当前是开发预览与规则配置，全部标记 planned，未开放采集、搜刮或击杀发放。概率是初始设计值，尚未经过经济平衡验证。F2 → 道具图鉴 → 选中道具 → 交互与掉落，可以查看来源、交互方式、工具、概率和数量。

## 三层引用

1. 物品：`itemCatalog[itemId]` 定义名称、用途、重量。
2. 掉落表：`lootTables[tableId].entries[itemId]` 定义 chance、min、max。
3. 交互：`lootInteractions[interactionId]` 绑定 assetId 或 profileId、action、toolId、lootTableId、depletedState。

配置位于 `src/game/loot/definitions.js`，注册和索引位于 `catalog.js`。不要把概率放进物品定义：同一种布料在衣柜和感染者身上的概率不同。

资源资产按稳定 assetId 绑定，变体默认共享基础规则。敌人和容器按明确的语义 profileId 绑定，不能用模型颜色、体型或皮肤猜测身份。装饰实例不会因为匹配了资产 ID 就自动开放交互；未来生成器必须显式创建持久化资源节点。未配置的资产默认没有掉落，包括地表碎石装饰。

## 概率语义

- chance 范围 0–1：1 必得，0 不产出。
- 当前统一为 independent：每个条目独立判定，不是各项权重相加后抽一种。
- 判定命中后，从 min 到 max 的闭区间均匀抽取整数数量；未命中为 0。
- 表可以全空，也可以同时命中多项。食品柜水 45%、罐头 40%，两者都没有的概率为 55% × 60% = 33%。
- 树木木料必得 3–5、树枝 60% 得 1–2；岩石石料必得 3–5。基础采集不让玩家忙完一场空。
- 普通感染者布料 25% 得 1–2，不掉武器、弹药或手雷。工人、医护仅用于未来明确身份的实体；不赋予现有随机尸群持续产出资源的能力。
- 数量是一次结算的总产出，不是单格上限；容器系统负责拆堆和承接背包溢出。

## 结算与保存约束（待实现）

每个实体 maxCompletions=1。砍树、采矿在采集完成时结算，不是每次打击；尸体与容器只抽一次，空结果也需要保存。工具检查在交互前执行。

未来使用世界种子、稳定实体 ID、规则版本生成确定性随机序列，并保存实际结果与耗尽状态。背包满、取消界面、重复打开、区块重载不能重抽。掉落领取与容器扣除需要原子提交。树木结算变树桩，其余资源耗尽，容器标记已搜刮；后续重生必须是明确的新周期，不靠卸载重置。

暂不接入生产抽样执行器、存档事务、采集动画、工具耐久或物资发放，避免在用途尚未完成前把材料投入正式经济。

## 运行期索引

- `getAssetLootInteraction(assetId)`：资产 / 变体直接取得交互规则。
- `profileLootIndex[profileId]`：敌人或容器身份直接取得交互规则。
- `lootTables[rule.lootTableId]`：取得待抽表，仅遍历该表条目。
- `itemLootSources[itemId]`：加载时生成反向来源索引，图鉴不扫描全表。

增加掉落表时检查物品 ID、概率与整数范围；交互检查掉落表、工具、交互类型和重复绑定。未来互斥抽取需要单独的 weighted 模式，不能把权重当成百分比展示。
