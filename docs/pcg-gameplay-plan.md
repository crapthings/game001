# PCG 玩法规划：边缘开场与 GPU 生成

状态：P1、P2 与环境 v2 首版代码已接入，尚未进行浏览器运行验收。2026-09-07。后续章节仍包含 P2–P4 的设计目标，以本节实施记录区分实际进度。

## 游戏入口与种子调整

- 随机种子统一为 12 位纯数字字符串，菜单与规划预览共用生成函数，无需 nanoid 依赖。
- 点击骰子更换种子后进入即创建新游戏；输入同一种子继续其已有进度。
- 进入游戏统一使用边缘开场世界，移除模式选择、旧版中心出生生成器及旧存档导入路径。
- 游戏只读写 IndexedDB 的 `[3, seed]` 记录；保留已有边缘世界进度。旧版中心出生记录不读取、不删除。
- 当前入口规则覆盖早期设计中的新旧模式并行方案。本轮仅静态检查，未运行测试、build 或 lint。

## 地形与环境 v2 实施记录

- `topography.version=2` 在原宏观场上叠加 12 个连续地貌核：每个宏观区域两条正高程山脊、一条负高程沟谷；幅度随区域主题变化。选址、道路寻路与最终地面共用同一原始场，避免渲染单独添加碰撞不一致的山体。
- `terrainVersion=4` 加入路缘之外约 0.32 米浅沟、0.45 米土坡及低幅细起伏；聚落与开场整平优先覆盖，驶入道路和停车核心保持平整。既有雾距与加载距离没有扩大，远景 LOD 尚未实现。
- `environmentVersion=2` 使用 80 米群落场和 23 米细斑块，共同驱动地面明暗、树木和地被密度。开场左右各增加平滑疏林岛权重；树群不随 Chunk 边界截断。
- 每个 32 米 Chunk 最多尝试 25 个树木候选与 64 个地被候选。候选坐标由全局格点及独立随机通道生成，限制偏移量保证同层候选间距；树冠可以自然重叠，两层之间尚无精细群落碰撞求解。
- 复用白桦、幼松、阔叶树、枯树、蕨类、枯草、荆棘、覆苔岩石、碎石与芦苇。道路边缘优先地被，离道路更远才允许树群。地面坡度过大、聚落过渡范围或道路净空内的候选会排除。
- `opening.clearanceVersion=2` 对自然物体按车辆通道、下车点、路障两侧步行绕行路线及镜头扫过范围分别排除；保守使用模型可见范围，避免只考虑细树干而让树冠挡住镜头。低矮草石允许留在其余空间。建筑及人工设施仍避让整个开场，感染者出生排除范围保持原设定。
- 调试底图新增“树群密度”，显示随机筛选与净空检查之前的候选密度；不是最终树木位置图。
- 旧 environmentVersion=1 世界继续旧采样和散布规则，不自动改变已保存世界。需使用未保存过的新种子生成并进入环境 v2；调试“生成预览”始终使用当前算法。
- 尚未执行浏览器画面检查或性能采样；不预设密度增加后的帧率。GPU 迁移、道路贴图升级与远景加载仍为后续任务。

## 当前剧情（以此为准）

前期不安排接应者或其他人类 NPC。车辆燃油耗尽，滑行减速，恰好停在一处被废弃混凝土路障挡住的公路上。玩家下车，自言自语几句，然后开始独自探索。

- 第一版独白：“没油了……偏偏在这儿。”“前面的路也堵死了。看来只能走过去了。”“一点动静都没有……先去附近看看，有没有能用的东西。”
- 镜头以玩家为主体，第二句略转向路障；不再创建接应者模型或碰撞体。
- 路障在停车中心前方 12 米，宽 9 米，横跨 6 米车道。路障左右保留步行绕行空间，玩家下车点仍在车旁安全区域。
- 新开场使用 templateVersion=2，记录 `story: out-of-fuel` 和 `roadblock`，不生成 npcAnchor。旧 v3 开场兼容读取，其路障由停车点派生，不重写快照；已完成的开场不强制重播。
- 可驾驶路面检查范围缩为入口到停车点；停车点之后的路障是有意阻断。断油目前通过滑行停车和独白表达，尚无独立燃油模拟或发动机音效。

## 当前实施记录

- 新生成世界使用 generatorVersion / planVersion 3、terrainVersion 4、environmentVersion 2；原 v2 中心出生快照已退出游戏读取路径。
- 四边各 8 个候选，按占地高差和湿度评分，最多尝试前 4 个；每个候选最多尝试 3 个聚落出入口。耗尽后明确失败，尚未加入额外兜底模板或阶段增量缓存。
- 开场总范围为横向 96 米、纵向 128 米，停车区 24×20 米，整地核心 48×96 米，过渡宽 8 米。入口在边界内侧 24 米；80 米直线驶入/驶离路线全部处于整平核心。
- 生成时在最终三角网格高度上采样 6 米宽路线和停车区域的坡度；这属于静态几何检查，不等于真实车辆运动验收。普通接入公路仅保证寻路连接，不承诺可驾驶。
- 聚落选址避让开场及整地余量；区域道路把开场当作障碍，指定接入道路可通过专属出入口。建筑和装饰安装、自然散布、感染者出生规划均消费开场排除范围。
- `world.opening` 保存世界空间锚点、整地与候选检查记录；镜头位置使用 `[x, 离地高度, z]`。运行时已接入脚本车辆、废弃路障和独白相机。
- 五层网格通过公式寻址，只记录开场相交单元。现有宏观、区域和生态数据保留原结构；完整街区和细层散布算法未重写。
- 调试页增加“聚焦开场”、16×16/32×32 网格、开场范围/锚点和“最终高度”底图。菜单直接进入边缘开场世界，同 seed 继续其进度。
- 实际游戏持久化使用 IndexedDB 的 `[3, seed]` 复合键。已移除旧字符串键读取和 localStorage 世界数据导入；localStorage 仅记录当前边缘世界种子。

P2 当前实现：

- `createOpeningDirector.js` 独立控制开场。车辆以 7 秒减速滑行曲线从入口行驶至停车锚点，每帧检查保守车体净空；玩家暂时隐藏，停靠后在下车锚点出现。
- 驶入采用朝地图内的跟拍镜头；停稳后用 0.35 秒淡出/淡入切入对话镜头。独白视线在玩家与路障方向间平滑调整；结束时淡出恢复原正交游戏相机。下车过程使用切镜头遮盖，尚无车门或下车骨骼动画。
- `OpeningOverlay` 点击画面逐句推进独白，不显示继续按钮；暂停和跳过按钮不会触发台词推进，转场或保存期间不推进。Esc 或切换到后台会暂停开场；恢复时返回开场阶段。开场期间暂停移动、感染者生成更新及生存时间消耗。
- 停车和开场完成分别保存稳定检查点，进度与下车位置一次写入。停靠前退出会从入口重播，停靠后退出从首句对话恢复，完成后不再重播。保存失败保留当前控制权并显示重试，不直接标记完成。
- 预加载范围为场景范围向外扩展 96 米并裁剪到地图边界，覆盖受限 FOV、64 米裁剪距离的镜头；引用令牌锁定区块，上限 128 个锁定区块。此为数量预算，尚不是精确显存字节预算。完成、跳过或销毁时释放。
- 车辆与路障注册动态碰撞体；开场结束后仍留在停车场，并随所在地块的加载状态显示/隐藏。车辆采用简单几何占位模型，尚无手动驾驶、悬挂或完整物理模拟。
- P1 已保存但没有开场进度的 v3 世界，首次进入会播放一次开场并使用下车锚点；v2 世界不再进入游戏。

本轮只做静态源码核对，未运行测试、build、lint、浏览器或性能采样。没有改动已有用户存档，也没有提交工作区中的其他改动。

以下设计尺寸、速度和预算是方案参数，不是已验证的性能或车辆能力。参数与当前实现不同之处，以以上实施记录为准；新功能不修改既有世界。

本次收紧范围：五层保留，但细层按需派生；先完成开场局部的可驾驶路线，完整区域公路工程后置；GPU 从道路表面单项迁移开始。玩法生成不依赖 GPU 才能完成。

## 1. 首个玩法闭环

玩家随车辆从地图边缘驶入，在预留的停车区停稳，展示玩家独白，随后交还角色控制。第一版建议采用脚本驾驶，后续手动驾驶复用同一个停车目标和场景约束。

开场本身使用受控模板；种子决定入口边、沿边位置、背景生态及接入世界的路线。必须稳定的停车、下车和对话空间不做无约束随机。

首版验收画面：地图上能看到边缘入口、驶入路线、停车区、玩家/路障锚点、镜头锚点和禁放范围。进入新世界时角色位于该场景的安全下车点；车辆和相机接入作为后续独立里程碑。

## 3. 空间层级

地图保持 2048×2048 米，X/Z 范围为 [-1024, 1024)。

| 层级 | 数量 | 单元边长 | 职责 | 算法/执行位置 |
| --- | ---: | ---: | --- | --- |
| 全局配方 | 1 | 2048 m | 开场、关键目标、必须连通关系、规则版本 | CPU Worker：约束、候选评分、有限回退 |
| 2×2 | 4 | 1024 m | 宏观地势与生态倾向 | CPU 生成参数；GPU 可批量采样 |
| 4×4 | 16 | 512 m | 城镇、危险梯度、主路连接图 | CPU：选址、图算法、粗网格寻路 |
| 8×8 | 64 | 256 m | 生态斑块、支路、兴趣点候选 | CPU 布局；GPU 密度/适宜度场 |
| 16×16 | 256 | 128 m | 街区、营地、停车和遭遇场景的空间管理 | CPU：模板、空间索引、局部约束 |
| 32×32 | 1024 | 64 m | 散布密度、局部排除范围、实例预算 | CPU 放交互物；GPU 筛选视觉装饰 |
| 运行时区块 | 4096 | 32 m | 加载、地面渲染、碰撞与实例安装 | CPU/GPU 分工，按需生成 |

规划网格不是地形分辨率、渲染 LOD 或 GPU workgroup。各尺度可以独立调整。第一版保留现有 32 米 Chunk，减少同时变更的接口。

单元数据包含稳定 ID、父 ID、边界、关联场景 ID 和约束 ID。关联采用相交查询；跨格对象只存一份实体数据，由多个单元引用。不要在每个 64 米格强制生成一个事件，也不要把模板限制在单格内部。

实现时将层级分为“全局规划”和“局部派生”：2×2、4×4、8×8 在创建世界时生成；16×16、32×32 默认只有网格寻址规则，在存在场景、约束或局部覆盖时存稀疏记录。不预创建 1280 个空单元对象，也不在创建世界时生成所有装饰。调试视图可按坐标公式画出完整网格。

细层默认继承上层规则，仅存覆盖值。每层可以查询已确定的父层数据与邻近约束，不能依赖邻格先加载。跨格散布按全局候选 ID 生成，冲突时按稳定优先级取舍，并查询覆盖最大排斥距离的邻格候选，避免加载顺序造成重复或接缝。

使用世界坐标采样，单元边界半开。相邻区块共享的顶点使用同一采样坐标；法线计算包含边缘邻域。LOD 后续单独处理接缝，不由规划树自动解决。

## 4. 开场场景契约

建议新增 `world.opening`，不复用现有感染者 `spawnPlan`。以下是字段约定，不是可直接运行的对象：

| 字段 | 含义 |
| --- | --- |
| `version`, `id`, `templateId`, `templateVersion` | 开场契约、实例身份与模板版本 |
| `edge` | north / east / south / west；约定 north 为 +Z |
| `origin`, `yaw` | 模板到世界的变换；位置为 [x, z]，角度为弧度 |
| `entry`, `approachPath` | 地图内入口锚点与驶入路径 |
| `parking` | 目标位置、朝向、车体允许区域、停靠容差 |
| `playerExit`, `roadblock` | 下车点与堵路设施；高度通过最终地面解析 |
| `connectionPortal` | 场景向区域路网开放的出入口 |
| `grading` | 整平核心、过渡范围、目标高程 |
| `reservations` | 车辆/角色/镜头净空、散布与敌人排除规则 |
| `shots` | 稳定镜头 ID、相机局部位置/高度、注视锚点、FOV、过渡时长 |
| `preloadBounds` | 模板提供的最小加载范围；运行时还需合并实际镜头可见范围 |

模板使用局部坐标，按选中的入口边整体旋转；停车朝向、玩家、路障和镜头一起变换。相机高度明确区分“离锚点地面高度”和“绝对世界高度”。

初始尺寸建议：场景预留约 128×96 米，入口向地图内缩至少 8 米，停车核心约 24×20 米，整地过渡约 16 米。先用保守车辆包围体确定净空，接入真实车型后再校准。

128×96 米表示包含整地过渡的总占地，不能先占满该范围后再向外扩展。旋转后的整地、车体净空和镜头最低加载范围都纳入候选检查；入口内缩取 8 米与车辆/相机实际所需余量中的较大值。接入公路走廊单独预留，可跨出场景占地。

数据分成两步：模板保留局部锚点与规则；选址完成后编译出世界空间的路径、整地约束和演员锚点，写入快照。运行时直接消费编译结果，不随模板文件更新重新解释旧世界。镜头编排通过带版本的镜头模板引用，已有版本保持可用。

入口位于世界范围内，不先引入地图外可驾驶区域。镜头朝内，边缘外背景若可见，使用独立远景方案。前期只使用玩家独白，不生成接应者。

`world.spawn` 兼容现有角色接口，取安全下车点；车辆起点由 `opening.entry` 表示。角色出生坐标不能同时承担车辆起点和停车点的含义。

## 5. 生成顺序与失败处理

1. 解析 seed、配方和算法版本；使用独立的 opening 随机通道生成四条边上的候选场景范围。
2. 生成宏观地形参数，对候选完整占地采样，按高差、坡度、湿度和预估接入代价排序。湿度不是水面；当前没有真实水文，不声称候选已避开水域。
3. 预留最高分场景及其接入口。生成城镇布局时禁止建筑、整地过渡和设施侵入预留区；此时确定聚落占地、目标高程和出入口，内部建筑暂不落位。
4. 生成必须连通的道路图，开场入口作为一等节点。先保证到最近可达聚落的连接，再补其余连接。
5. 求道路路径和开场路线纵断面，生成场景/开场道路/聚落统一整地约束；衔接端共享高程。首版普通区域公路保留原有贴地方式，不标记为已通过车辆校验。
6. 基于最终地面检查纵坡、弯道、路宽、车体扫掠净空及下车可达性；失败按稳定候选顺序局部重试。
7. 生成建筑、交互物、感染者和视觉散布，统一消费预留范围。
8. 汇总分层引用、镜头加载范围、质量报告和世界快照。

候选与重试次数必须有上限，并写入生成报告。道路失败优先换入口组合和局部路径，其次更换开场候选，必要时重新安排冲突聚落。兜底模板应有预留的平缓接入走廊，仍需通过相同检查；全部失败就返回明确原因，不用穿楼直线凑出“成功”。

初版预算建议为每边 8 个候选、共 32 个；详细求解仅处理评分最高的 4 个，每个最多尝试 3 个接入口组合，最后尝试一次保守模板。优先按操作次数限制，保持跨设备确定性；用户取消或运行时超时可以中止生成，但不能按机器速度选择不同布局。失败报告包含阶段、候选 ID、违反约束和尝试次数。

避免全局反复生成：换开场候选时重算关联道路和受影响的聚落草案；已通过的无关区域保留。第一版可只缓存阶段结果，不建设通用增量生成框架。

城市内部设施可先做草案，但最终建筑放置必须在区域公路走廊确定后。现有流程先建聚落再删掉挡路建筑，下一版应减少这种事后修补。

## 6. 车辆道路与预留规则

规则分两类：软成本决定优选路线；硬约束决定是否允许生成。第一版可暂定开场驶入路线纵坡上限 8%、停车核心上限 2%、弯道半径下限 12 米，均等待车辆运动参数校准。坡度百分比与角度不能混用。首版的硬约束覆盖入口到停车点及其驶离段；连接到聚落的普通公路先保证拓扑连通，完整驾驶校验放在 P4。

16 米 A* 用于寻找走廊；停车与弯道使用更细采样做几何检查。只采道路中心线不够，还需检查道路横断面、车辆扫掠包围体及地面过渡。

预留区须有用途和优先级：停车核心禁止道路横穿，连接口允许指定道路进入，镜头净空排除遮挡体，敌人排除区作用于整个开场范围。不能仅按物体中心判断；建筑/树木的包围体与预留范围相交即需处理。

整地不能按数组顺序逐个覆盖。先固定停车与聚落平台高程，再用端点高程求道路纵断面，最后向自然地形平滑过渡。平台核心与不属于它的道路核心相交时应报冲突，不能依靠优先级隐藏问题；合法接入口共享目标高度。过渡区采用明确且版本化的混合规则，最终统一采样并重新检查坡度。

预留查询先用二维包围范围筛选，镜头遮挡再用带高度的体积约束检查。首版使用保守包围体即可，不需立即实现逐三角形可见性求解。

区分永久不生成感染者与开场期间暂停激活。首版可永久排除开场场景内的感染者出生点；周边感染者的移动还需运行时开场保护，静态出生排除不能阻止其走入。

## 7. CPU/GPU 数据契约

三类数据分别管理：

- `WorldPlan`：CPU 权威的拓扑、对象 ID、路径、约束、锚点；持久化。
- `SurfaceData`：最终地面高度及规则版本；CPU 移动和 GPU 绘制遵守同一坐标与插值约定。
- `SurfaceCache`：法线、颜色、道路纹理、视觉装饰候选；可重建，不写入 localStorage。

首阶段保留 CPU 权威高度，把法线、道路贴图、生态颜色等批量计算放到 GPU。规则地形网格的索引可复用，无需每次重新生成；这项改进独立于 WebGPU。

后续 GPU 生成权威高度时，在准备区块期间异步读回一次并缓存，CPU 获得数据后才允许进入该区块。CPU 地面查询和 GPU 网格必须使用同一三角形划分；不能用双线性插值替代当前 `surfaceHeight()` 的三角形插值而不做同步修改。

G3 的进入条件是先确定权威高度的重建方式：若 CPU 与 GPU 不能按约定精度复现相同高度，就持久化 GPU 生成的权威高度块，或继续由 CPU 生成权威高度、GPU 只负责表面。普通可丢弃缓存不能承担恢复碰撞地形的唯一依据。设备丢失后先恢复权威数据，再开放移动。

高度样本量与地图米数分开考虑：全图 1 米间隔、包含两端边界时是 2049×2049 个样本，单份 Float32 约 16 MiB；还未包含法线、颜色、掩码和临时缓冲。第一版不预生成全图高分辨率表面，保留按区块缓存。

GPU 任务输出尽量直接用于绘制，不走“GPU 计算 → CPU 全量读回 → GPU 再上传”的表面路径。保留 CPU 后端作为兼容和设备丢失恢复路径；后端变化不得改变城镇、道路和碰撞物布局。

## 8. GPU 迁移次序

| 顺序 | 工作 | 边界 |
| --- | --- | --- |
| G0 | 记录 Worker 各阶段时间、安装时间、上传字节和排队长度 | 先得到实际瓶颈；本轮不执行测量 |
| G1 | WebGPU 引擎能力检测、资源生命周期、CPU 后端回退 | 世界配方与渲染后端解耦 |
| G2a | 只迁移道路纹理生成并缓存 | 首个完整 GPU 切片，验证输入、输出、显示、失效与回退 |
| G2b | 根据计时迁移法线、材质权重 | G2a 有收益后扩展；不要求三项同时重写 |
| G3 | 高度场、场景和道路整地 | 完成 CPU 权威高度缓存契约后接入 |
| G4 | 草、小石子等视觉装饰的候选筛选和实例绘制 | 有碰撞/交互/存档身份的对象仍有 CPU 数据 |

道路着色只上传附近的路段列表或分桶索引，避免每像素遍历全世界路网。共享高度与颜色基础场，减少同一地点的重复采样。邻域运算采用带边界数据的分块 pass，workgroup 大小由具体内核和设备限制决定。

迁移收益同时观察生成耗时、区块就绪延迟、主线程安装耗时和帧时间尾部；Worker 变快而画面更卡不算通过。单 Chunk 地形只有 33×33 个顶点，优先复用规则网格、合并邻近区块任务，再评估法线计算是否值得单独 dispatch。纹理分辨率第一版保持现有 256×256，避免把降画质与 GPU 加速混为一项收益。

缓存键至少包含世界身份、地面/道路/材质配方版本、区块坐标和分辨率；修改道路时只失效其覆盖区块及所需边界邻域。限制在途任务、缓存字节和每帧提交量，失效任务完成后不安装过时结果。

首版由渲染引擎拥有 GPU 设备和缓存，Worker 负责规划；暂不引入独立 Worker GPU 设备与渲染设备之间的资源交接。

Babylon 当前代码使用 `Engine`。计算着色器路线需要引入 `WebGPUEngine`；支持探测、初始化失败和设备丢失均需有处理。技术参考：[Babylon WebGPU](https://github.com/BabylonJS/Documentation/blob/master/content/setup/support/webGPU.md)、[MDN WebGPU API](https://developer.mozilla.org/en-US/docs/Web/API/WebGPU_API)。

## 9. 流式加载与相机

加载源由单个玩家扩展成多个请求：玩家近邻、车辆预测路径、开场场景、当前镜头及其下一个镜头。

每个请求包含范围、优先级、用途和释放令牌。开场预加载锁定不受玩家距离卸载规则影响；跳过、完成、场景销毁和加载失败都释放令牌。以实际镜头视锥和裁剪范围估计背景需求，不能只加载相机脚下的区块。

区块状态建议为 queued → generating → prepared → installing → ready。ready 区分 visualReady 和 collisionReady；玩家/车辆可进入范围需要两者均就绪，远景请求可只要求 visualReady，开场还需演员/镜头资源就绪。异步结果携带世界版本和请求代次，丢弃过时结果。

车辆预测距离取“车速 × 实测加载提前量 + 安全余量”，设置上限及 GPU 每帧提交预算。接近未准备区块时减速或暂停脚本驾驶，不允许进入空地。

请求按用途分配预算：当前人物和车辆安全范围最高，其次当前镜头，再次下一镜头和预测路径，最后远景。合并重叠范围并引用计数。锁定只防止卸载，不绕过内存上限；开场最低必需集合超预算时，在播放前缩短镜头可见距离或选择预定义紧凑镜头，仍不足则明确加载失败，不在播放中强制卸载锁定区块。

当前游戏是正交相机。对话可使用独立透视相机，但跨投影方式不能仅插值 position/FOV：首版采用短淡入淡出切换；同一透视相机内的镜头再做平滑运镜。对话结束恢复正交参数、尺寸适配、输入和角色跟随。

开场状态：preloading → arriving → parked → dialogue → returning → complete。停稳需同时满足位置、朝向和速度容差。所有输入由当前状态拥有，切镜头时暂停原来的跟随逻辑，避免两个系统同时写相机。

保存稳定检查点，不保存每帧镜头状态。重新进入时，未完成驶入可从入口重播；已停靠可恢复对话；完成后正常恢复角色位置。跳过开场必须先确认停车点已加载，然后原子地设置车辆/角色位置和完成状态。

## 10. 确定性与存档

随机通道格式统一为 seed + 配方版本 + 层级 + 全局单元坐标/稳定实体 ID + 用途。开场、城镇、道路、感染者、装饰各用独立通道，不依赖生成任务完成顺序。

并行候选经过稳定 ID 排序与确定性冲突裁决后进入权威布局。GPU 浮点结果不能直接决定关键对象是否存在；阈值附近的关键决定由 CPU 规则或已保存的规划结果确定。

当前布局使用 generatorVersion=3、planVersion=3；改写最终地面规则时另升 terrainVersion。保留已有 v3 边缘世界的配方采样，不再读取 v2 中心出生世界。

存储统一使用 IndexedDB `[3, seed]`，校验要求生成版本 3 和开场数据；同 seed 读取已有边缘世界，随机新 seed 创建新游戏。schemaVersion 取决于容器结构，不能简单用生成版本代替存档结构版本。

细格只存必要引用和配方参数，可推导的边界不重复序列化。继续 localStorage 时控制快照体积并处理写入失败；大块 SurfaceData/缓存迁入 IndexedDB 等存储应作为独立任务。

## 11. 分阶段交付

| 阶段 | 可见交付 | 完成条件 |
| --- | --- | --- |
| P0（已完成） | 设计文档 | 明确层级、开场契约、GPU 边界和版本方案 |
| P1 | 新版世界中的边缘停车场规划和安全出生点 | 五层寻址及稀疏引用、场景预留/整平、局部驶入路线校验、路网接入、散布排除、调试覆盖层、新旧存档路由 |
| P2 | 车辆驶入、停靠、对话相机的完整开场 | 加载锁定、状态机、输入控制、跳过和恢复；先用脚本车辆 |
| P3 | 道路表面 GPU 后端，按收益扩展 | 道路纹理迁移，能力回退，阶段性能报告；法线/颜色按计时决定 |
| P4 | 地形 GPU 化和驾驶扩展 | 权威高度恢复方案、区域道路驾驶校验、车辆参数校准、速度预测加载 |

P1 应整体交付，不能只挪动 `world.spawn` 或添加未被散布/整地消费的 opening 元数据就标记完成。P3 的收益按数据报告，不预设加速倍数。

P1 内部按以下顺序实施：版本路由 → 开场模板与候选 → 场景/道路约束编译 → 统一高度及散布查询 → 调试显示。每步明确输入输出，最后一起作为可用功能交付。16×16 与 32×32 此时只承担必要的查询职责，完整街区算法、全图水文、侵蚀模拟、手动驾驶和通用剧情编辑器均不属于 P1。

P1 的人工检查必须区分“开场可驾驶”与“区域路网连通”；调试图分别显示开场硬约束检查结果、普通公路未校验状态和失败原因。P2 可以使用占位车辆与玩家独白镜头，先验证完整切换和恢复，不等待最终美术。

后续人工验收关注：四边与跨格场景、停车区净空、道路衔接、CPU/GPU 地面一致、切镜头背景就绪、跳过/恢复、旧快照无变化。遵守项目要求，不运行测试、build 或 lint；实际浏览器检查和性能采样需在对应实现阶段记录，不能用本轮静态分析替代。
